# Тестовые сценарии RevitPlanningPlugin

## ТС-01: Подключение к API

| # | Шаг | Ожидаемый результат | Статус |
|---|------|---------------------|--------|
| 1 | Открыть плагин, перейти «Подключение» | Форма настроек отображена | — |
| 2 | Ввести корректный Base URL, API Key, нажать «Сохранить» | Статус: «Настройки сохранены» | — |
| 3 | Нажать «Проверить соединение» | Статус: «Соединение установлено» (зелёная полоса) | — |
| 4 | Указать неверный API Key, нажать «Проверить соединение» | Статус: «Ошибка авторизации» (красная полоса) | — |
| 5 | Указать несуществующий URL, нажать «Проверить» | Статус: «Сетевая ошибка» или «Таймаут» | — |

## ТС-02: Загрузка списка контуров

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Настроить подключение (ТС-01) | Соединение работает |
| 2 | Перейти «Контуры», нажать «Загрузить список» | Список контуров заполнен; статус: «Загружено N контуров» |
| 3 | Проверить отображение имени и площади каждого элемента | Данные корректны |

## ТС-03: Загрузка и проверка контура

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Выбрать контур в списке | Кнопка «Загрузить выбранный контур» активна |
| 2 | Нажать «Загрузить выбранный контур» | Контур загружен во внутреннюю модель плагина; информация отображена в карточке; Revit-модель не изменена |
| 3 | Проверить корректность геометрии по карточке и валидации | Контур замкнут, площадь и количество сегментов совпадают с ожидаемыми |
| 4 | Загрузить контур с невалидной геометрией | Сообщения валидации отображены красным; генерация заблокирована |

## ТС-03A: Извлечение контура из Revit-модели

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | На активном уровне выделить замкнутый набор линий, разделителей помещений или стен | Элементы выделены в Revit |
| 2 | Нажать «Извлечь контур из выделения Revit» | Плагин создает внутренний BuildingContour, показывает площадь и количество сегментов |
| 3 | Проверить модель после извлечения | Новые элементы Revit не созданы; выделение использовано только как источник контекста |
| 4 | Запустить генерацию | В запрос `/generate` передан `context.contour`, `context.revit_context` и `llm_prompt` |
| 5 | Выделить незамкнутые элементы и повторить извлечение | Валидация показывает ошибку, генерация заблокирована |

## ТС-04: Генерация вариантов планировки

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Загрузить валидный контур (ТС-03) | Контур отображён |
| 2 | Перейти «Генерация», установить 3 варианта, мин. площадь 10 м² | Параметры применены |
| 3 | Задать тип генерации, текстовый prompt и режим проверки | Параметры попадают в контекст запроса |
| 4 | Нажать «Сгенерировать» | Preflight-валидация проверяет количество вариантов, площади, МОП, prompt и состав помещений; при ошибках запрос к API не отправляется |
| 5 | Дождаться результата | Статус: «Получено 3 варианта»; вкладка «Результаты» содержит 3 записи |
| 6 | Получить ответ с невалидным JSON или нарушением DTO-контракта | Результат блокируется до маппинга в доменную модель |
| 7 | Получить ответ с потерянными помещениями в Strict-режиме | Генерация блокируется сообщением валидатора |

## ТС-05: Просмотр и сравнение вариантов

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Получить варианты (ТС-04) | Галерея вариантов заполнена |
| 2 | Выбрать вариант 1 | В UI отображается выбранный вариант, миниатюра и метрики; постоянные элементы Revit не создаются |
| 3 | Переключиться на вариант 2 | UI-предпросмотр обновлён без дублирования и без изменения модели |
| 4 | Сравнить метрики: S, полезная площадь, количество помещений, score | Значения различаются между вариантами |

## ТС-06: Применение варианта (разделители + помещения)

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Выбрать вариант, нажать «Создать черновик в Revit» | Перед записью выполняется строгая валидация выбранного варианта |
| 2 | Подтвердить диалог записи | Room Separation Lines и Room-элементы созданы в транзакции Revit |
| 3 | Отклонить диалог записи | Модель Revit не изменена |
| 4 | Проверить помещения в Schedule / Room Schedule | Помещения перечислены с именами и площадями |
| 5 | Применить другой вариант повторно | Предыдущие элементы, созданные плагином, удалены; новые созданы без дублирования |

## ТС-07: Блокировка некорректного применения

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Сгенерировать вариант с помещением вне выбранного контура | Валидация показывает блокирующую ошибку |
| 2 | Нажать «Создать черновик в Revit» | Запись заблокирована, диалог подтверждения не появляется |
| 3 | Проверить модель | Новые элементы Revit не созданы |

## ТС-08: Обработка ошибок

| # | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| 1 | Отключить интернет, запросить контуры | Сообщение: «Сетевая ошибка»; возможность повторить |
| 2 | Передать 401 от API | Сообщение: «Ошибка авторизации» |
| 3 | Передать 500 от API | Retry (до MaxRetries); затем сообщение: «HTTP 500» |
| 4 | Нажать «Отмена» во время генерации | Операция отменена; статус: «Отменено» |

## ТС-09: Валидация контура

| # | Контур | Ожидаемый результат |
|---|--------|---------------------|
| 1 | Незамкнутый (зазор > 1 мм) | Ошибка: «Контур не замкнут» |
| 2 | Менее 3 сегментов | Ошибка: «менее 3 сегментов» |
| 3 | Самопересечение | Ошибка: «Самопересечение» |
| 4 | Площадь < 1 м² | Ошибка: «Площадь слишком мала» |
| 5 | Обход по часовой стрелке | Предупреждение: «CW_ORIENTATION» |

## ТС-10: Тестирование Mock-клиента

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Подключить MockPlanningApiClient вместо реального | Плагин работает без внешнего API |
| 2 | Загрузить список → 6 демо-контуров | Контуры включают прямоугольный, Г-образный, органичный, сплайн и контур с внутренним двором |
| 3 | Загрузить каждый и провести ТС-04–ТС-07 | Все сценарии проходят на мок-данных |

## ТС-11: Дипломные сценарии хорошей генерации, ошибки и галлюцинации

| # | Mock-сценарий | Шаг | Ожидаемый результат |
|---|---------------|-----|---------------------|
| 1 | HappyPath | Включить Mock API, выбрать `HappyPath`, загрузить валидный контур, сгенерировать варианты | Варианты проходят валидацию, отображается предпросмотр, применение в Revit доступно после подтверждения |
| 2 | GenerationError | Выбрать `GenerationError`, нажать «Сгенерировать» | Плагин показывает красный статус с причиной ошибки AI-сервиса, Revit-модель не изменяется |
| 3 | Hallucination | Выбрать `Hallucination`, включить Strict-режим, нажать «Сгенерировать» | Валидация блокирует результат и объясняет, что помещение выходит за выбранный контур |

## ТС-12: Production-интеграция LM Studio / Gemma

| # | Шаг | Ожидаемый результат |
|---|------|---------------------|
| 1 | Запустить LM Studio Local Server, загрузить `google/gemma-4-e4b` | `GET http://localhost:1234/v1/models` возвращает список моделей |
| 2 | В плагине выбрать источник генерации `LM Studio`, URL `http://localhost:1234/v1`, указать имя модели | Настройки сохраняются; таймаут production-режима не меньше 180 с |
| 3 | Нажать «Проверить соединение» | Статус: «Соединение установлено» |
| 4 | Извлечь контур из выделения Revit | Контур загружен во внутреннюю модель плагина; Revit-модель не изменена |
| 5 | Задать параметры генерации и нажать «Сгенерировать» | Плагин отправляет `GenerationRequestContext` в `/v1/chat/completions` |
| 6 | LM Studio возвращает валидный JSON-конверт | Плагин показывает варианты, выполняет DTO-валидацию и доменную валидацию |
| 7 | LM Studio возвращает markdown/reasoning вокруг JSON | Плагин извлекает первый JSON-объект и валидирует его |
| 8 | LM Studio возвращает текст без JSON или нарушает контракт | Плагин показывает ошибку, Revit-модель не изменяется |
| 9 | Выбрать валидный вариант и подтвердить применение | Room Separation Lines и Room создаются только после строгой валидации и подтверждения |
